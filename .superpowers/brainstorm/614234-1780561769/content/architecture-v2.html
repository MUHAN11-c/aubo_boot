相比当前架构的核心改进

  • +状态管理层 — ConnectionStore + RosDataStore + ServiceStore + UIStateStore 四大 Store
  • SWR 缓存 — 每个 topic 缓存最新值 (LRU + TTL)，消费端无需管理订阅生命周期
  • 服务级智能回退 — Foxglove CDR 优先, schema缺失/服务不可达时自动回退 rosbridge JSON
  • 发布路由 — Foxglove clientPublish CDR 优先, rosbridge JSON 回退
  • 消息分发去重 — RosbridgeAdapter 不再通过 ivgTransport 的 handler registry 重复分发
  • ros_connector.js 废弃 — 全部页面统一走 RosManager → TransportHub

需注意的约束

  • 纯 HTML/JS MPA — 不能引入 Vue/Pinia/React/Zustand, Store 用 vanilla JS EventTarget 实现
  • 渐进迁移 — 旧 API (ivgTransport 直连) 保留 deprecation warning, 逐步切换
  • BroadcastChannel — 跨标签页状态同步需保留 (log-bus.js 已有机制)
  • 全局单例 vs 页面级实例 — RosManager/RosDataStore 模块级单例, UIStateStore 页面级

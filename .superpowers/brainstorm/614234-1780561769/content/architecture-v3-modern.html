核心设计决策: 模式锁定 vs 自动回退

场景 模式 行为 日志输出
订阅 /joint_states FOXGLOVE FoxgloveAdapter.subscribe() → CDR channel 订阅
如果 foxglove_bridge 不可达 → 报错, 不回退 rosbridge		 [bridge:foxglove] sub /joint_states (sensor_msgs/JointState) ✓ ch=3
订阅 /joint_states ROSBRIDGE RosbridgeAdapter.subscribe() → JSON subscribe
如果 rosbridge 不可达 → 报错, 不回退 foxglove		 [bridge:rosbridge] sub /joint_states (sensor_msgs/JointState) ✓
订阅 /joint_states (foxglove 不可达) FOXGLOVE FoxgloveAdapter 连接失败
→ TransportHub dispatchEvent 'bridge:error'
→ RosDataStore 标记 topic stale
→ UI 显示错误状态		 [bridge:foxglove] sub /joint_states ✗ FAILED: foxglove_bridge unreachable
调用 /latte/run_workflow FOXGLOVE FoxgloveAdapter.callService() → CDR service call
如果 schema 缺失 → 报错, 不回退		 [bridge:foxglove] svc /latte/run_workflow ✗ FAILED: service not advertised by foxglove_bridge
AUTO 模式降级 AUTO FoxgloveAdapter 优先, 不可用时显式降级到 rosbridge
dispatchEvent 'bridge:degraded' 通知 UI		 [bridge:auto] foxglove unreachable → DEGRADED to rosbridge
[bridge:rosbridge] sub /joint_states ✓

BridgeLogger — 全链路可观测 (★ 新增)

每条数据的 bridge 归属可追溯, 问题可排查
BridgeLogger 设计:

  class BridgeLogger extends EventTarget {
    _records = []                    // 环形缓冲 最近 2000 条
    _stats  = {                      // 累计统计 per bridge
      foxglove:  { subs:0, pubs:0, svcs:0, bytes:0, msgs:0, errors:0 },
      rosbridge: { subs:0, pubs:0, svcs:0, bytes:0, msgs:0, errors:0 }
    }

    log(entry)                       // 记录单条 → dispatchEvent 'bridge:traffic'
    getStats()                       // 返回累计统计
    getActiveSubs()                  // 当前活跃订阅 + 各自使用的 bridge
    getRecords({bridge, direction})  // 按条件过滤历史记录
  }

日志记录格式:

  {
    ts: 1717500000000,               // epoch ms
    direction: 'sub',                // 'sub' | 'pub' | 'svc'
    topic: '/joint_states',
    msgType: 'sensor_msgs/JointState',
    bridge: 'foxglove',              // 实际使用的 bridge
    mode: 'FOXGLOVE',                // 当前模式
    bytes: 1234,                     // 消息大小 (CDR 或 JSON)
    latencyMs: 2.3,                  // 解码延迟
    status: 'ok'                     // 'ok' | 'error' | 'degraded'
  }

日志流向 (3 条输出路径):

  BridgeLogger.dispatchEvent('bridge:traffic')
       │
       ├──→ LogEventBus.addLog('bridge', ...) → IndexedDB 持久化 + BroadcastChannel 跨页同步
       │
       ├──→ ivg_status_bar 实时指示器: 🟢 Foxglove 3.2MB/s | 45 subs | 0 errors
       │
       └──→ 调试面板 "Bridge 流量" 标签页: 按 bridge/direction 过滤, 实时滚动

响应式数据流管道 (模式锁定版)

WebSocket → CDR Decode → TypedMessage → Store Cache → dispatch event → UI Render
完整数据流路径 (FOXGLOVE 模式):

  ROS2 Node → foxglove_bridge (CDR) → FoxgloveClient → FoxgloveAdapter (MessageReader)
       → TypedMessage → BridgeLogger.log({bridge:'foxglove', ...})  ← ★ 每条消息记录
       → TransportHub (dispatchEvent 'message')
       → RosManager._dispatchRos → RosDataStore.set(topic, data)
       → RosDataStore.dispatchEvent('data:/joint_states')
       → [joint-chart Canvas2D 重绘] [debug_panel 状态栏] [其他订阅者]

错误路径 (FOXGLOVE 模式 + Foxglove 不可达):

  RosManager.init({mode:'FOXGLOVE'})
       → TransportHub.setMode('FOXGLOVE')
       → FoxgloveAdapter.connect('ws://...:8765')
       → WebSocket error: Connection refused
       → FoxgloveAdapter dispatchEvent 'status:error'
       → BridgeLogger.log({bridge:'foxglove', status:'error', ...})
       → TransportHub 不切换适配器, 不复用 RosbridgeAdapter  ← ★ 不回退
       → dispatchEvent 'bridge:error' → UI 红色指示器
       → 后续 subscribe/publish/callService 全部在 FoxgloveAdapter 上失败
         (明确报错, 问题可定位)

Service 调用状态机 (模式锁定):

  ServiceStore.callService(name, type, request, timeout)
       → RosManager.callService()
       → TransportHub.callService()
       → BridgeMode === FOXGLOVE
            → FoxgloveAdapter.callService() ONLY
            → 成功 → BridgeLogger.log({bridge:'foxglove', status:'ok'})
            → 失败 → BridgeLogger.log({bridge:'foxglove', status:'error'})
                   → ServiceStore → FAILED + dispatchEvent('service:error')
                   → 不回退 rosbridge  ← ★
       → BridgeMode === ROSBRIDGE
            → RosbridgeAdapter.callService() ONLY
            → 同上, 失败直接报错
       → BridgeMode === AUTO
            → FoxgloveAdapter 优先
            → 不可用 → BridgeLogger.log({..., status:'degraded'})
            → RosbridgeAdapter 降级

v3.1 相比 v3 的核心变更

  • ★ 模式锁定, 禁止静默回退 — FOXGLOVE/ROSBRIDGE 模式各自锁定通道, 失败直接报错, 不回退
  • ★ AUTO 模式显式降级 — 仅 AUTO 模式允许降级, 降级时 dispatchEvent 'bridge:degraded' 明确通知
  • ★ BridgeLogger 全链路可观测 — 每条 sub/pub/svc 记录 {topic, bridge, mode, bytes, status}, 可追溯到具体 bridge
  • ★ 错误可定位 — 模式锁定意味着: 选了 foxglove 但没数据 → 一定是 foxglove 的问题, 不用排查 rosbridge
  • ServiceRouter/PublishRouter 不再自动回退 — 模式决定通道, 路由逻辑大幅简化

FAQ

  • Q: rosbridge 还保留吗? 保留, 作为独立模式 (BridgeMode.ROSBRIDGE), 用户可手动切换, 但不会自动回退
  • Q: AUTO 模式什么时候降级? FoxgloveClient 连接失败 (3次重试后) → 降级 rosbridge, 并 dispatchEvent 通知 UI
  • Q: 降级后 foxglove 恢复了会切回去吗? 会, AUTO 模式下 FoxgloveAdapter 健康检查恢复后自动切回, 同样 dispatchEvent 通知
  • Q: BridgeLogger 日志存多久? 环形缓冲 2000 条 (内存) + 通过 LogEventBus → IndexedDB 持久化 (5K 环形缓冲)

## 摘要

本工程为**套袋桃采摘机器人**的感知—抓取—自主导航联合工程：固定座 AUBO E5 六轴臂 + 腕载 RGB-D 相机 + 三把剪切手末端，以「场景观察锁定 → 选果 → 近距重建许可 → staging 接近 → 进入-剪切 → 记账」的批次工艺自主采收套袋桃。

**现状一句话：固定座采摘核已建成并经真机预抓取多轮验证；软件结构与安全护栏完整、测试塔成型；剪切手族与双目前端已就位、待真机剪切与田间收口；导航分项预留，真底盘授权后按保留口径恢复。**

- **已建成**：应用九包整栈（调度 / 感知 / 臂执行 / 观测）+ 仿真场景与感知验证矩阵（基线冻结）+ 测试塔（回放塔、CI 双 job、E2E 六阶段方案）。
- **近期落地**：三把剪切手替换双套袋圆柱（默认自适应档、咬合档主测）；相机前端默认切主机双目（感知锁定 2.8 s vs 48 s）；Survey 后场景障碍快照护相机，经真相机轮验证。
- **安全基线**：功能安全在控制柜与示教器；ROS 侧四级授权矩阵 + 许可令牌族 + 四层接近约束；未授权不动臂。
- **下一步重点**：真机满程进入-剪切验收、三剪切手真机标定、刀具切断反馈接线（接触验收三前置）；随后 NX 主控部署验证与 E2E 各期推进（详见第 10 章）。

### 1.2 工程概况

**作业对象与工艺**：果园套袋桃。产品方案随 2026-09 决策 0033 由「空心圆柱套袋取走」切换为**剪切手族剪柄采果**——末端开口对准袋颈/果柄区域接近（进入行程随工具档案），剪切机构剪断果柄完成采收。三把剪切手（连杆对切 / 咬合对夹+喉道导轨 / 圆盘自适应贴果）经工具档案机制整栈切换；其中自适应剪切手挂增量 IMU，接触段由 IMU 姿态跟随弥补视觉误差。

**已建成能力**：

- 固定座采摘核整栈可运行（应用九包 + `peach_sim` 场景包 + 驱动与标定工具）：开批、场景观察与身份锁定、目标选定、近距多视重建、抓取许可、预抓取停靠（默认干跑）、授权后进入-剪切、记账；
- 接近主路径为「staging 转移」（关节空间 PTP + 沿轴 LIN），配套四层安全约束与真机标定的接近门；
- 相机前端双轨（设备端结构光 / 主机双目 SGBM）同话题同契约，已端到端实测选优且**默认已切主机双目**（0036；设备端显式传参备用）；
- 仿真侧 `peach_sim`（Gazebo 场景 + Blender 真网格外观、按真实数据集校准）已建成感知验证矩阵并冻结基线。

**导航预留**：按 2026-09 决策转预留——不实现底盘与雷达驱动、不接 Nav2，调度到位一步直通可抓取；恢复须真底盘书面授权。两档导航设计与三门协同口径保留在本书第 3、4、8 章，作为恢复后的实施依据。

本工程不另建采摘产线。

按单车（现行固定座）、单臂、单工位、批次作业设计。每批由人工启动，处理视野内若干目标后结束；批次策略（采收率、单果时限、扇区时限、视点档）运行期可调。导航两档设计保留为预留口径，现行固定座直通。

### 2.3 安全与合规规定

1. **功能安全在柜与示教器，不在 ROS。** 急停（ISO 13850）、保护停止（ISO 10218）、使能装置由控制柜安全回路承担；`RobotMoveStop`、取消 action、8090 等一切软件停轨是应用层受控停，**不得称为急停**，不得替代硬件急停。
2. **未授权不得真机运动或 SetIO。** 授权是人的口头/书面确认，不是配置项。使能三档（execution/grasp/tool）默认全关；`autostart` 为部署参数默认关。
3. **故障后禁止 resume 原轨迹。** 处理现场 → 示教器复位 → 取消并丢弃在途 goal → 重新授权后重新下发。不用 dashboard 远程上电/解锁。
4. **人在工作空间须另行风险评估。** 带剪切机构末端不因协作臂出厂认证而豁免；接触力/压强限值须实测。
5. **测完即停。** 任何测试/程序结束停干净并 `pgrep` 复核；启动前同样预检。

### 2.4 设计原则

1. **调度为唯一指挥。** 批次状态机为纯核（`harvest_fsm.react`），节点只做 ROS I/O；批次动作唯一客户端是调度（8090 调试桥是唯一例外，且不旁路安全门）。
2. **先停车，后近距；先许可，后接触。** 重建积分只用精确时间戳 TF，不虚构深度。
3. **契约先于实现。** 跨包只走 `peach_interfaces` IDL + manifest 双向核对；数据流单向（调度→技能的 IK 查询是唯一反向例外）；呈现不回写；感知不发运动、不写账本。
4. **失败可定位、可跳过。** 每个目标有稳定 `failure_code`；拒因分级（许可过期可重派 vs 明确拒因失败）。
5. **停走式感知是产品相机模型。** 节拍按实测帧率 + 静止门设计；相机前端双轨同契约，切换不改编译面。
6. **跟 ROS 2 主流。** 对照 UR ROS2 Driver、MoveIt 2/MTC、Nav2、ros2_control、Autoware、OSU apple-harvest；非完美适配处标 UNWIND，改到那一块即改主流（立场见 `AGENTS.md` 偏离表）。

### 2.5 运行环境

室外果园，行间作业，光照变化大，枝叶遮挡。**现场主控为 Jetson Orin NX 16GB**（Ampere GPU + Tensor Core、8× Cortex-A78AE、100 TOPS 量级）：整机栈（感知推理、重建、调度、臂执行、观测）当前**全部部署其上、暂不分级**；后续拟增 RK3588 作前端初步数据采集/预处理为 NX 减负（**预留，未实装**，分工与链路待定）。开发、仿真与测试仍在开发工控机（Ubuntu 24.04 + ROS 2 Jazzy，Python 数值栈钉版 venv `aubo_py3.12`，3090 级 GPU）。部署注意：JetPack（L4T）自带的 Ubuntu 版本与 Jazzy 官方发行（Noble 24.04）不一致——NX 上走容器（`ros:jazzy` arm64 镜像 + CUDA 设备直通）或源编，属部署前置验证项（见第 10 章）。腕上 RGB-D 相机（Percipio PS800-E1）。臂侧沿用现有急停与停轨（透传取消 + 硬件 `RobotMoveStop`）。`numpy == 1.26.4` 为 ABI 红线（Jazzy cv_bridge 按 numpy 1.x 编译），NX 侧同守。仿真/bag 回放全图 `use_sim_time:=true`，真机禁止误开。

## 3 总体方案

### 3.1 方案比选

**导航**按 2026-09 决策转预留（仓库不实现底盘/雷达驱动与 Nav2 接线，`_cmd_navigate` 固定座直通 `NAV_OK`）。两档设计保留为恢复口径：简易档（固定座、无路径规划）与主流档（RTK+多传感融合、全局规划/局部避障/行间巡航、底盘急停切断）。恢复时在归档包内部接发行版 Nav2，不加第五个采摘包。

**末端**经 2026-09-28 决策 0033 由双套袋圆柱切换为三把剪切手，共用工具档案机制与冻结帧名（`tool_axis` / `sleeve_mouth` / `cutting_plane` / `tcp`），TCP 姿态全族 `Rx(−90°)`、开口朝法兰 +Y；切换须整栈重启，作业中不切换。

| 精度 | 入口 z std 4.37 mm | 入口 z std 1.92 mm（temporal_k=3 再降约 48%） |
| 覆盖 | 远端覆盖更好 | 近距覆盖最优；结构性左盲带 |

| 状态 | 备用（显式传参） | **现行默认**（0036 用户裁定；切换须重做手眼标定） |

### 3.2 推荐方案与系统组成

现行方案：保留并深化固定座采摘核（应用九包 + 驱动层 + `peach_sim`）；调度为指挥中心并含生命周期管理与过程监控；相机前端双轨同契约可选；导航转预留；末端按工具档案配置三把剪切手之一；工艺顺序为开批、拍照位、场景锁定、选果、观察与重建并行、预抓取停靠（默认干跑）、授权后进入-剪切、记账。

逻辑分层（现行方向；分层细节与包表见 `docs/architecture.md`）：

```
契约层  peach_interfaces（唯一 IDL + manifest 双向核对）
L0 传感驱动层  相机前端（percipio | peach_stereo）/ 臂驱动 ros2_control / TF（只读红线）
L1 感知算法层  检测→身份→重建→融合→许可（事实生产）
L2 决策调度层  联合约束选果→FSM→派发→账本（决策生产）
L3 运动执行层  授权矩阵→笛卡尔规划→执行→IO（动作生产）
L4 呈现层      RViz 稳定视图 + HTTP 作业票（只读横切）
L5 过程数据层  会话 bag（三档限速）+ 批次账本 + 停栈自动报告（只读横切）
旁路  peach_sim 仿真场景 / peach_vegetation 枝叶掩膜 / IVG 视觉抓取（均不进整栈）
```

解耦不变量：R1 跨层只经契约包；R2 数据流单向（调度→技能 IK 查询唯一例外）；R3 呈现不回写；R4 筛选维度归位；R5 纯核零 ROS；R6 运动收敛授权矩阵、能力绑 Active；R7 记录只增不删（bag 按预算回收是唯一例外并写审计）。

包结构方向（现行包表与「不做什么」以 `docs/architecture.md` 为准）：采摘应用 9 包（interfaces / common / harvester（大脑一进程三节点）/ arm / bringup / observability / vegetation / system_tests / stereo）+ `peach_sim` 场景包 + 臂/相机驱动 9 包（只读红线）+ 标定工具 + 可选 `serial_imu` / `imu_follow` + 旁路 IVG 三包。整栈唯一入口为 `peach_bringup` 的 harvest_system launch。

## 4 工艺流程

### 4.1 工艺总流程

批次由人工启动（`RunHarvest`，指定批次剖面与视点档），launch 绝不自动开批。主要工序（一批）：

1. 到位（现行固定座直通）；
2. 拍照位 Survey 并复核关节，重启收齐窗，等场景锁定；
3. 选果：有效深度窗 ∩ TCP 可达预检（服务不可用回退标定半径窗），同级按检测框面积降序；
4. 近距重建与主动观察并行（两档观察策略）；
5. 接近：staging 转移主路径，至预抓取停靠（默认干跑，人工评方向后 ACK）；
6. 授权后进入-剪切，原路撤退；
7. 记账（逐目标失败码入账）。

批间规则：Survey 失败中止本批；观察或许可失败放弃当前目标；停靠未 ACK 不回访、不派下一颗；一颗结束回发现态再 Survey；连续空扫达上限或策略完成则结算，超时/超率目标进补采清单（8 类归因）。

到位（L1）仅表示可以开始场景观察，不表示某一目标可抓取。

### 4.2 靠近工序（预留）

现行固定座：调度到位一步直通 `NAV_OK`；四个导航 IDL 标预留。预留两档恢复后：L1 在开批之后、拍照之前进行，L2 为目标靠近；调度将当前目标的坐标与状态发往导航，感知不直接向车辆发送坐标。坐标或状态缺项、过期、坐标系不明时不进入靠近中，直接失败；已停止后给出可抓取，主流档在未确认静止前不给出可抓取。可抓取后才允许近距重建；车辆位移后 L2 场景坐标作废，须重新观察。

### 4.3 进入-剪切工序

进入条件为可抓取（现行直通）且当前目标未变更。近距重建给出袋口、袋轴、入口与许可令牌族（绑定当前目标，`valid_until` 窗口 + `model_revision`；`allowed` 为汇总位，臂侧分级复检）。接近主路径为 staging 转移：先回拍照位（有接近记录则原路返程），PTP 到预抓取正下方轴上 staging 点（多滚转候选并行 IK、自碰过滤、逐试），再沿轴 LIN 升到预抓取；staging 全候选失败且满足几何前提时兜底直连 LIN。进入沿工具开口方向直线推进，撤退倒放同一接近轨迹。

- **shear_v1 / bite_shear_v1**：进入-剪切-撤退均走采摘核 MTC LIN（不调 imu_follow）。
- **adaptive_shear_v1**：决策 0026 起批次自动接触窗——FULL 在预抓取验证后开启 imu_follow（enable → insert_start → 行程等待 → insert_stop → 剪切 → insert_retract → disable，失败路径同样 disable 收口），回到预抓取才关窗，再 MTC 回 stow；插入推进沿锁定的工具开口方向低速直线（0.01 m/s，行程钳=档案 L_insert，部署值 0.09），姿态照常跟 IMU；断流或达行程自动停。

剪切机构默认关闭（`tool.enabled=false`）；SetIO 的 ACK 只表示柜侧收下命令，不是切断确认（切断反馈 DI 预留接 `/aubo_io_controller/io_states`，未接线时 `tool.enabled=true` 终局 `CUT_FEEDBACK_TIMEOUT`）。接近段执行四层安全约束（8.4 节），接近门按真机数据标定：绕行比 2.6 / 弦偏离 0.32 m / 回退 0.12 m（2026-09-18 标定，30/30）。

### 4.4 联合运行时序

调度与各分项的运行时序、检查点上报（现行实际发射 CK_AT_PREGRASP / CK_SLEEVE_PLANNED / CK_SLEEVED / CK_CUT_ACCEPTED / CK_CUT_CONFIRMED / CK_RETREATED / CK_STOWED 七档；CK_AT_STAGING 与 CK_RETAINED 为 IDL 预留、暂不上报）与终局分级（recovery > 取消 > 成功 > 失败）见 `docs/architecture.md` 分项节；六张流程图（系统组成/批次主流程/靠近状态/套入流程/联合时序/三门协同）封存于归档目录（附录 B）。

## 5 分项设计（方向与边界）

本章每节只给方向、关键决策与边界；现行参数、阈值与决策依据见 `docs/architecture.md` 对应分项节与决策表（0001–0036）。

### 5.1 作业调度（`peach_harvester` supervisor）

大脑进程内调度节点管理批次寿命、当前目标与档位。批次状态机为纯核（9 批次态 / 12 目标相）。选果为联合约束（显式指定优先且须过资格谓词；有效深度窗 ∩ IK 可达预检；同级按检测框面积降序）。账本逐目标写 `runs/<request_id>/ledger.json`（失败码、阶段耗时；断点恢复），补采清单 8 类归因。操作台服务面（开批/控批/使能/批次策略/单步）与观察两档 `view_policy` 语义见 io.md 与 architecture.md。生命周期由整栈 `nav2_lifecycle_manager` 托管（名单：场景 → 重建 → 技能 → 调度），闩锁旗标是开批闸门；四托管节点已接 bond 心跳（超时默认关，开启条件见 10 章遗留）。批次实验变体（默认全关）：`skip_observation`（Build 采集期即并行派 FULL，臂侧有界等精化兜底）、`skip_reconstruction`（跳过重建直接接触，须与臂侧 `allow_unrefined_geometry` 同开）；接触段部署默认 `execute_pregrasp_only`（干跑语义，见 2.2）。

### 5.2 感知（`peach_harvester` vision + 相机前端）

**场景观察**：检测 → 分割 → hybrid 掩膜 → 袋位姿（圆柱 RANSAC + 重力显式降级；窄头=扎口、宽头=袋底）→ 世界系身份匹配（χ² 门 + 匈牙利分配 + EMA，累计确认转正）→ 收齐窗口锁定。单帧几何状态只当初值与画面，不授权运动。

**近距重建**：采帧门（锁定/精确 stamp TF/静止门/严掩膜门）→ 有界 ICP 拒帧 → TSDF 在线积分 → 多视角袋关键点 Huber 融合 → 动态工具预算许可；独立机位数与角基线同时达标才 finalize；许可窗口默认 120 s + 单调修订号。

**场景障碍快照**（`peach_scene_obstacles`，独立进程、不进 lifecycle 名单，2026-09-29 上栈）：Survey 成功后经闩锁 `/peach/scene/obstacles_refresh` 触发，用最近一帧点云快照式重建障碍（BOX 对象入 PlanningScene world，体素 0.06 m），受查对仅相机连杆×障碍——现行避障以护相机为主；与臂侧「只写 ACM diff」分域双写，互不覆盖。

**相机前端**（L0，整栈 `camera_frontend` 切换，**现行默认 stereo**——0036）：percipio 设备端结构光与 `peach_stereo` 主机双目 SGBM 话题同构、深度口径同为 uint16×0.25 mm（0.25 mm→m 换算在感知消费端统一完成），感知/重建零改动接入；彩色内参共用唯一事实源。切换前端采果前须重做手眼标定。

### 5.3 导航（预留）

包体归档，不在构建、不进整栈 launch 与生命周期名单；现行只在接口清单预留区留名，无生产方。恢复条件：真底盘书面授权，从归档取回并在包内部接发行版 Nav2；仓库仍不写底盘/雷达驱动或底盘速度话题。恢复后按 4.2 口径与 8 章互锁实施。

### 5.4 机械臂（`peach_arm`）

六轴臂 AUBO E5 固定座快换。技能节点（Lifecycle，GPL 参数单源）挂三个 action（`SurveyScene` / `ExecuteTarget` / `MoveTo`）与服务面（`CheckReachability` 为 srv、两种预览、取消周期、恢复 ACK、拍照位、一次性 arm）；接触周期为显式阶段执行器（`stages.cpp`：PrepareCycle → [变体可跳观察] AcquireViews → FinalizeAndValidate → ReconfirmTarget → MovePregrasp → VerifyPregrasp → [干跑 HoldPregrasp 置 recovery 等 ACK（ACK 走 `~/acknowledge_recovery`，由调度侧把关） | FULL：PlanSleeve → SleeveLinear → ActuateCutter → VerifyCut → ReverseRetreat → ReturnStow → ReleasePayload（收集位开刀，TOOL 级）→ VerifyOutcome]），检查点上报口径见 4.4。

执行权收敛于授权矩阵（`ExecutionAuthority`，四级：公共门 ∧ Active ∧ robotReady ∧ ¬cancel 之上，TRANSIT + execution_enabled；CONTACT + grasp_enabled ∧ 许可复检（radial 余量 >0）；TOOL + tool_enabled ∧ axial 余量 >0 ∧ 预抓取已验证（批次4 分级许可），SetIO 前再过本级，授权凭据取周期快照——决策 0032）。拒因分级：许可/令牌过期 → `SKIPPED_QUALITY` 可重派；明确拒因 → `FAILED`。撤退段 TRANSIT 级不做决策复检。任何路径不绕过该矩阵；8090 亦只是又一客户端。

接近约束四层见 8.4；行程护栏与速度档现行值见 architecture.md。规划面：MoveIt（OMPL + Pilz PTP/LIN + STOMP；mock 用 `mock_components/GenericSystem` + 标准 JTC，real 用透传 FJT）；MoveIt TEM 关闭（决策 0029，与透传控制器打架），超时防线= `moveit.execute_timeout_s` 有界执行（决策 0027，默认 90 s）。点云 octomap 护臂/相机现行临时关闭（恢复=把点云源加回 `sensors_3d.yaml`），工具链 × octomap ACM 豁免已实现。健康双轨：作业票 JSON + `diagnostic_updater`；bondcpp 已接线。

### 5.6 过程观测与数据记录（`peach_observability`）

HTTP 过程页（回环 8090，安全头）两视图：「过程」多面板（节点与档位、事件流、阶段时序、TCP 俯视、账本直播、感知节拍、系统负载）；「调试」单步转发既有动作/服务（无令牌；运动类另需 `debug.motion_enabled`；全部操作含被拒落审计；不旁路 `ExecutionAuthority`）。

会话 bag（决策 0019 + 0031 限速）：随栈启停开合 `runs/session_*/bag/`（rosbag2 MCAP）；按话题三档限速进袋（控制流族 20 Hz / PlanningScene 族 1 Hz / 感知派生族 2 Hz，各族首帧必录），只限进袋不影响实时流与验收门；停栈自动生成报告；体积超预算（现行 100 GB，战役上限）自动回收最旧 bag（文本/账本/报告永不删，逐条写回收审计）。诊断双轨走 `/diagnostics`。

标定唯一事实源：手眼外参 `hand_eye/active.yaml`（缺失不得开批）；彩色内参 `color_camera_info.yaml`（两前端共用）；重标定走 vendored `camera_calibration` + `apply_intrinsics` 原子落盘。

### 5.7 枝叶掩膜（`peach_vegetation`，影子）

GPU 枝/叶二维分割（Frangi 血管ness + 叶绿启发式），发布掩膜/overlay 与诊断。不写 PlanningScene、不进整栈（独立 launch，与 YOLO/MobileSAM 分进程避免同卡对打）。为将来树干/粗枝占用建模提供输入（预留）。

### 5.8 仿真场景（`peach_sim`）

室外套袋桃果园场景包（决策 0028–0030）：`config/orchard.yaml` 全量场景参数 → 纯核确定性产出 Gazebo Harmonic 世界（5 行 × 7 株桃树、袋果每株 6–12 随机采样——现行 manifest 全园 326 袋、作业面 11 袋 + 立柱拉线 + 土壤草带）与目标清单 GT；袋具锚真机口径（工作树实测区间），测试镜像对账工具档案。采摘工位 = 开源履带底盘改型 + AUBO E5 + 腕载相机 + 快换 + 剪切手，帧契约与真机同构；工位锚在作业位（履带不可驾驶），`gz_ros2_control` 未接。外观走 Blender 4.5 无头程序化建模（真网格 + PBR 贴图，按真实检测数据集校准袋体尺寸/吊挂偏角/配色）。用途：感知验证矩阵（M0–M3，852 帧首轮 GATE PASS、基线冻结）与手工系统测；非能力包、不进 `harvest_system`/lifecycle。

### 5.9 公共设施（`peach_common` / `peach_interfaces`）

`peach_common`：yaml 直读 `attach` / 参数规则表 / QoS 工厂 / 路径单源（对齐 nav2_common；不跑节点）。`peach_interfaces`：跨包唯一 IDL + manifest 双向核对脚本，改字段流程与消费者列以 manifest 为契约。

## 8 运行控制与安全设计

### 8.1 运行控制三门

三门协同：**导航门**给出可抓取（现行直通）、**抓取门**给出许可并执行套入-剪切（许可令牌族唯一权威：`allowed` 汇总 + radial/axial 分档，臂侧分级复检）、**姿态门**仅末端 C 在接触段有效（IMU 跟随辅助）。任一扇门的通过不改写其余门的结论。手眼标定误差与工具安装零位误差分别记录；方向定位对错以预抓取停靠位真机目视/测量为准。

### 8.2 互锁

表8-1 运行互锁（摘要）

| 套入-剪切（adaptive） | 否 | 否 | — | 自动接触窗连续 |

### 8.3 使能、授权与心跳

三档使能 `execution / grasp / tool` 默认全关，依赖链 execution→grasp→tool 参数校验强制；使能意图源=操作台 `SetEnables`，1 Hz 心跳闩锁广播，臂侧看门狗断流回落本地参数权威。`execution_armed` 一次性人工 arm；取消旗标各动作终局自动清；三执行线程有界回收。故障后恢复：接触失败撤离未确认 → `recovery_required`，须人工 ACK 才允许 Survey/下一颗。

### 8.4 接近段四层安全约束

| 层 | 保护 | 检查 | 生效期 |
|---|------|------|--------|
| ① 果实胶囊 | 果实 | 工具有限圆柱（包络=档案 `body_length`/`body_radius` 随档案注入，决策 0033/0034）vs 感知果实胶囊；逐段 FK 审查；sim 审查体同源 | 仅接近段；进入/撤退豁免 |
| ② 从下方反爬 | 果实 | TCP 轴向投影限界（锚果底） | 仅接近段 |
| ③ 场景障碍/点云占用 | 相机（避障目的=护相机；臂/末端轻微碰撞工艺已接受） | 点云源保持空（**不用 octomap updater**，0035 否决——两轮翻车教训）；`peach_scene_obstacles` 场景快照（Survey 后触发、体素 0.06 m 先行滤除、受查对仅相机×障碍、ACM 豁免合并式回写） | 规划期；运行时开关 `obstacle_guard_enabled` 默认 true；真机遗留=快照形态复核/开关切换实测/带障碍规划耗时 |
| ④ 近果降速 + 接触止损 | 果/硬件 | 近果 LIN 降速；腕轴电流守护（默认关，阈值须真机标定） | 执行期 |

### 8.5 出错处理

表8-2 出错处理（方向）

| 故障 | 处理 | 范围 |
|------|------|------|
| L1 失败（预留档）/ Survey 失败 | 结束本批 | 整批 |

### 8.6 安全分层与红线（设计基线）

功能安全（柜/示教器）与应用护栏（ROS 2：授权矩阵、使能默认关、命令超时与心跳、规划碰撞）与网络安全（SROS2/DDS-Security，非功能安全）三层分立；应用护栏不宣称 SIL/PLe。硬红线：驱动栈只读；未授权不动臂/SetIO；硬件急停不经 ROS；停轨是应用层受控停不称 e-stop；保护停止后不 resume 原轨迹；测完即停清进程。完整安全分层与操作纪律以 `AGENTS.md` 第 2 章为权威。

7. bond Python 侧真修（`from bondpy.bondpy import Bond`）后才可开 `bond_timeout`；期间死检由 supervisor 心跳看门狗承担。
8. 监控页局域网暴露的访问控制（现行仅回环）。
9. Jetson Orin NX 部署落地验证：Jazzy 容器化/源编、CUDA 推理节拍（YOLO / MobileSAM / Frangi / 双目 SGBM）、cv_bridge × numpy 1.26.4 ABI、8090 与 bag 落盘 I/O；表2-2 锚点须在 NX 重标。RK3588 前端分工（预留）随之定案。
10. 物理仿真联动（`gz_ros2_control`）与系统测收进 colcon。
11. 实车行驶指标、RTK 固定解、行间避障达标（随导航恢复）。

## 11 结论与建议

本工程在已建成的固定座采摘核上（应用九包、staging 接近主路径、四层安全约束、真机标定接近门），完成了相机前端双轨实测选优、自适应末端与 IMU 姿态跟随/插入推进实装（批次自动接触窗）、三把剪切手工具族切换与三档自动化测试、仿真场景与感知验证矩阵、观测与过程数据闭环（三档限速会话 bag）、测试与质量基建（测试塔 + 回放塔 + CI 双 job + E2E 六阶段方案）；车辆到位闭环转预留，待真底盘授权后按保留口径恢复。抓取门以许可令牌族为唯一权威（`allowed` 汇总 + radial/axial 分档 + 120 s 窗口 + 单调修订号，臂侧分级复检），姿态门仅作接触段辅助；授权矩阵四级收敛所有运动/IO 入口。

**结论：固定座方案已建成并经真机预抓取验证；软件结构与安全护栏完整、测试塔成型；剪切手族与 stereo 前端待真机剪切/田间验证；导航预留口径完整。方案可行，深度满足开展详细设计。**

建议：详细设计以三活文档与 `AGENTS.md` 演化立场为现行依据展开；本设计书作为大方向主本随里程碑滚动修订；遗留问题按第 10 章顺序逐项核销，其中真机满程剪切、刀具 DI、剪切手标定三项为接触验收前置。

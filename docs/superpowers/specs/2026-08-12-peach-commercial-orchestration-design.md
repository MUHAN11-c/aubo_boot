# 桃子采摘商业化联动架构设计

## 目标与边界

面向套袋桃形成可持续运行、可观测、可人工接管的自动采摘系统。系统不得修改冻结的
AUBO 真机驱动栈，不得自动调用上电、松刹车或安全恢复；真机上电始终由现场人员完成。

## 职责划分

- `peach_harvest_orchestrator`：批次唯一所有者，负责门控、选靶、调度、暂停、恢复与审计。
- `peach_approach_grasp`：单目标运动能力，通过 Action 提供规划、执行、工具和撤离反馈。
- `peach_pose_ros2`：检测、估计和稳定目标身份，不拥有批次流程。
- `peach_reconstruction_ros2`：按目标建立显式会话，输出质量与精化结果。
- `peach_perception_web`：任务中心和控制代理，不复制业务状态机。

跨包长过程使用 Action，瞬时命令使用 Service，状态、事件和诊断使用 Topic。新接口集中在
`peach_harvest_msgs`，旧 Trigger/JSON 接口保留一个迁移周期。

## 状态模型

批次状态：等待就绪、发现、运行、等待安全暂停点、已暂停、维护、完成、故障、需要恢复、
被中断。单目标阶段：选靶、观察、重建完成、质量验证、靠近、工具动作、撤离、完成登记，
并以成功、质量跳过、不可达跳过或失败结束。

系统启动后保持自动模式；机器人状态、数据源与能力节点全部通过健康门才开始批次。人工调试
必须先进入维护模式，编排器释放自动所有权。普通暂停在安全检查点生效；立即取消是独立高风险
命令。需要人工检查的故障进入 `RECOVERY_REQUIRED`，确认前禁止继续运动。

## 调度、并发与数据

感知采用容量为一的最新帧 worker，过载时丢弃旧帧；重建采用单写者串行 worker，保证
ICP/TSDF 顺序和会话一致性。ROS 回调只做校验、快照和入队，重计算不阻塞执行器。编排器
对每条命令使用 `request_id`、`revision` 和目标/周期标识，实现幂等和过期命令拒绝。

参数分为 `HOT`、`IDLE_ONLY`、`STARTUP_ONLY`。Web 可修改前两类；命名档案持久化到工作区
`peach_profiles/`，应用时返回逐项结果并生成审计事件。

## Web 与安全

界面采用“任务中心 + 上下文操作抽屉”：主区显示批次、当前目标、时间线、质量和阻塞原因；
只有进入维护模式才展示手动调试按钮。无登录部署仅适用于可信隔离局域网，同时保留同源限制、
会话 nonce、状态 revision、高风险二次确认、速率限制和不可变审计日志。所有按钮的可用性由
服务端 `CommandPermission` 决定，悬浮提示解释话题、参数、禁用原因及影响范围。

## 故障策略

数据短暂缺失可限次重试；质量不足和不可达记录后跳过目标；工具或接触结果不确定时先撤离并
要求人工确认；机器人安全状态异常立即停止派发新运动并等待本体安全回路与人工处理。任何软件
路径都不得尝试自动恢复急停、防护停或上电状态。

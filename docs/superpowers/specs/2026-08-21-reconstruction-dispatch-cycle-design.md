# 重建调度与采摘节拍修正设计

## 目标

修复 `BuildTargetModel` 已接收但未及时绑定目标、机械臂仍执行无效观察的调度故障。在不降低重建质量门和运动安全门的前提下，使单目标完整周期达到接近人工操作的 45–60 秒目标。真机测试允许观察、接近、插入和撤离运动；`tool.enabled=false`，禁止 SetIO。

## 根因与约束

首轮真机运行中，执行器于目标派发后立即启动 `OBSERVE_ONLY`，而重建节点保持 `IDLE`、未绑定目标、视角数为 0。五次观察运动均因 `reconstruction_unbound` 超时。停栈时 `BuildTargetModel` 才进入绑定代码，表明重建状态锁竞争与缺少启动握手共同造成错误时序。

不得降低以下质量约束：至少 4 个重建视角、基线与深度覆盖门、精化 RMSE 与内点率门。保持自由空间速度缩放 0.10、接触段 0.05，并继续使用机器人状态、新鲜度、碰撞和恢复门。

## 设计

### 重建锁边界

`_on_target_observations` 只在 `_state_lock` 内更新目标、掩膜和中心缓存；自动驱动 `_auto_drive()` 在释放外层锁后调用。这样其 TF 查询、采帧和 TSDF 工作不会把 Build 初始化挡在状态锁之外。

### Build 就绪握手

执行器发送 Build action 后先等待首个反馈。只有反馈表明目标已绑定且状态为 `COLLECTING`，才能发送 `ExecuteTarget.OBSERVE_ONLY`。启动确认最长等待 2 秒；超时则取消 Build、记录 `build_start_timeout`，机械臂保持原位。Build 反馈须包含当前视角数与状态；目标 ID 由 action goal 和重建诊断交叉核对。

### 观察节拍

全局拍照位作为初始重建视角，主动观察要求 3 个有效移动视角，最多允许第 4 个补偿视角。重建最少视角仍为 4；不足时质量门拒绝接触。观察预算设为 35 秒，等待新帧继续按实际约 2.43 fps 自适应，不使用固定长等待。

## 失败处理

- Build 未就绪：不移动，取消并记账。
- 有效视角或质量不足：跳过 FULL，不执行接触。
- 接触运动启动后失败：要求恢复并沿透传取消链执行 `RobotMoveStop`。
- 工具节点始终跳过 IO，但接近、插入和同轴撤离照常执行。

## 验证

先做构建与静态检查，再运行单目标真机周期。验收记录包含：Build 绑定延迟、各视点耗时、有效/拒绝视角、重建前后 entry/neck/axis/travel 的位置差和角度差、RMSE、内点率、轨迹点数与执行时间、机器人错误/急停/恢复状态。成功标准是重建质量门通过、MTC 接近/插入/撤离完成、无 SetIO、无悬挂 action，且周期尽量落在 45–60 秒内；若精度与节拍冲突，以质量和安全为先。

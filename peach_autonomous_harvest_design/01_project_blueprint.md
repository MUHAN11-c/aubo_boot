# 01 项目总纲

## 1. 产品目标

构建能在指定果园工作区域完成自主导航、作业点定位、目标发现、选择性剪切采摘、承接收集、资源处置与异常恢复的机器人系统。以一台移动采摘机器人作为第一条完整产品线；多机协作保留扩展边界，不作为首版必需条件。

基准工艺为套袋桃剪切采摘。完整范围包括底盘、定位传感、近场视觉、机械臂、工具、承接容器、卸载/补能设施与操作台。具体硬件组合、作物适配和工艺偏置后续用现场证据确定。云平台可用于管理和复盘，现场运动与恢复不能依赖云或网页持续在线。

## 2. 用户与职责

- 作业员：设置区域与任务、核对现场、发起/暂停/取消、处理换箱与必要恢复。
- 维护人员：设备、标定、工具、地图/站点维护与受控配置变更。
- 研发人员：模块验证、仿真/回放、故障复现和结果对照。
- 项目管理人员：任务质量、遗漏、效率、资源、人工介入与验收进度。

## 3. 五级工作对象

果园任务 → 行/分区 → 作业点 → 单果周期 → 动作阶段。

果园任务账本描述整体目标和已完成/未完成原因；作业点记录导航与作业结果；单果记录采摘终局；动作阶段保留过程证据；容器/物流另记果实去向。导航成功、剪切指令受理、采摘确认、入箱确认不能互相替代。

## 4. 目标架构原则

1. 全局任务、导航任务、作业点与单果周期分别拥有自己的状态和结果，上级协调，下级完成能力任务。
2. 感知产出事实，模型产出可操作条件，业务作决定，执行侧复核并实际输出运动/工具命令。
3. 首版底盘移动与机械臂采摘互斥；移动前臂/工具进入可移动状态，到位后再通过稳定工作交接。边走边采后续另作系统验证。
4. 长期果园资产、导航实时障碍和当前目标局部模型分开管理；地图/工具/作业点变化会使相关旧模型与计划失效。
5. 剪切、带离、承接、释放/入箱分别保留结果证据；结果未知时进入受控恢复，不猜成功。
6. 容量、电量、定位和健康会改变作业计划；资源模块提出请求，由任务调度安排卸载/补能或人工处理。
7. 成熟库优先：Nav2承担导航，MoveIt/MTC承担机械臂规划与阶段；标准ROS接口、生命周期和MCAP承担基础设施。本阶段不决定具体算法和配置。
8. 应用护栏与功能安全分层。未授权不真机运动或SetIO；硬件急停独立；本仓驱动只读、不远程上电或解锁、不自动继续旧危险动作。
9. Web展示和表达意图，业务服务与执行侧管理权威；页面关闭不等于机器人任务结束。
10. 先贯通整个产品框架，再替换模拟能力、接真实硬件并优化模块。接口先表达职责与结果，不提前膨胀字段和第二套框架。

## 5. 成功标准与暂不深入项

完整性：任务从准备到收尾都有责任模块；导航与采摘的交接、资源不足、结果未知与人工恢复都能解释。可替换性：相机、导航定位、几何算法、工具与容器实现可以改变而不改全局业务结构。可观测性：任务、作业点、单果与物流能对应到同一会话和工况。

性能指标先定义分母与证据：区域覆盖与遗漏、到位作业完成、尝试采摘/确认脱离/确认收集、果损/误切、任务时间、能耗、人工介入。阈值和数值目标不凭论文或mock设定，待代表性果园样本验证。

本阶段后置：SLAM/GNSS/视觉定位选型、路线求解与局部控制器、果梗/袋口模型、工具几何阈值、数据库字段、进程/线程、API编码、QoS细表、部署性能和视觉微交互。需要后续决定的问题仅记录模块接口与验证条件。

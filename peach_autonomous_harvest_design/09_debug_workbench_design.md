# 09 研发调试台与验证工作流

## 调试台的目的

帮助工程师回答：哪个模块或交接失败、输入是否齐全、输出是否符合当前上下文、哪些证据已经获得、下一步如何验证或复现。调试是全项目能力，不是暴露所有ROS服务/参数/SetIO。

## 工作台结构

左侧模块目录与跨模块模板；顶部试验来源、任务/工作点/目标与配置摘要；中部输入/输出检查、计划/阶段和事件；右侧期望结果与拒因；下部原始状态、执行/验证轨迹、回放与证据。支持只读检查、模拟运行、结果核对、复现导出和收口。

## 六种试验模板

### D01 单模块输入输出

责任：M05。

步骤：选择模块与上下文 → 核对必需输入 → 预览输出 → 模拟能力任务 → 核对结果来源 → 保存并收口。

核对：输入缺失不得继续；模块结果有来源与终局。

### D02 导航 → 作业点就绪

责任：M03 / M04 / M11。

步骤：确认臂工具可移动 → 导航任务预览 → 模拟到达结果 → 检查底盘稳定 → 建立新场景 → 交接与收口。

核对：导航到达与工作点就绪分别确认，稳定失败不能启动采摘。

### D03 模型 → 单果执行

责任：M05 / M06 / M07 / M08。

步骤：绑定目标上下文 → 核对模型与条件 → 只规划预览 → 模拟预抓取 → 核对实际阶段 → 取消或周期收口。

核对：查看选择不等于执行绑定；模型失效不沿用旧计划。

### D04 工具 → 收集结果

责任：M08 / M09 / M10。

步骤：确认阶段与权限 → 预览剪切任务 → 模拟指令受理 → 核对工具与物理证据 → 核对承接入箱 → 结果和差异入账。

核对：指令受理、剪断、入箱分别记录；未知结果进入恢复。

### D05 资源 → 全局调度

责任：M02 / M03 / M04 / M10。

步骤：读取容量/电量 → 生成资源请求 → 模拟当前周期收口 → 交接离场 → 模拟卸载/补能确认 → 重新编排待办。

核对：资源模块不抢导航；到站不当服务完成。

### D06 完整任务闭环

责任：M01 / M02 / M03 / M04 / M05 / M06 / M07 / M08 / M09 / M10 / M11 / M12。

步骤：准备任务 → 导航与工作交接 → 观察与单果作业 → 收集与资源处置 → 异常/取消/人工恢复 → 报告与退出。

核对：任务—工作点—单果—物流口径一致，模拟与真实来源分开。

## 故障情境

- **导航受阻**：M03 / 目的地路线被阻挡。预期处置：有限重规划/换点/人工处理，工作点未就绪。
- **到位但未稳定**：M04 / 移动—采摘交接条件不满足。预期处置：保持采摘未开放；重新定位或等待稳定。
- **观察输入缺失**：M05 / 必需相机/空间观测不可用。预期处置：拒绝建模和新接触，等待有效输入。
- **目标/模型失效**：M06 / 工作点上下文或模型版本已变化。预期处置：撤销旧方案，重新观察/评估。
- **剪切结果未知**：M09 / 指令受理后没有独立确认。预期处置：受控保持待人工，不正常撤离或重发。
- **容器容量不足**：M10 / 继续收集的资源条件不满足。预期处置：安全收口后由M02安排卸载/换箱。
- **补能需求**：M10 / 持续作业电量条件不满足。预期处置：业务边界内收口，安排补能或人工处置。
- **关键模块失联**：M11 / 关键能力健康不可确认。预期处置：撤运行条件并停止受影响任务，恢复后重新评估。
- **浏览器数据陈旧**：M12 / 当前显示不能证明后台最新状态。预期处置：普通操作受限；查询实际终态，取消保持独立。
- **操作结果未知**：M12 / 浏览器等待超时，后端终态未知。预期处置：不自动重发，查询或发独立取消。

故障注入只在演示/明确隔离的模拟测试域提供。生产页允许读取真实故障和运行业务恢复，不允许向真机注入传感失效、权限或工具状态。场景模板与配置版本保存，重置回基线不等于恢复硬件或重新授权。

## 证据链与验收口径

输入来源/版本→动作意图→受理与阶段→结果→独立验证→收口/恢复。每份证据包含试验对象、任务上下文、输入/配置/数据来源、步骤、故障设置、事件/结果与未验证项。缺记录就明示缺失，不填默认正确值。模拟能力只验证流程与界面，不证明剪断、力、避障或功能安全。

## 成熟工具协作

主Web保留业务视图、操作规则和跨模块追踪；Foxglove用于多面板/回放，PlotJuggler用于时序分析，RViz用于空间与规划，Groot仅用于已经采用BehaviorTree.CPP的部分。它们是可选研发入口，不新增平行命令权威。版本、许可、数据访问和只读配置在接入阶段核对，不在此阶段实现。

## 首轮界面实现顺序

先共享上下文、页面路由和操作反馈；再任务/现场/故障三页；然后目标/执行/物流；再调试模板与证据包；最后回放、比较和维护配置。先用离线/假API验证界面流程，再接受控业务接口，最后隔离仿真与真机联调。

## 从v1方案继承的验证资产

可复用历史mock/回放/真相机mock臂/真机分层验证思路，以及节点日志、任务事件与账本、诊断、会话bag/自检四类证据。D01核对观测来源与时间，D03核对模型/工具/标定版本，D04核对指令受理、独立反馈、剪断和入箱，D06核对失联/撤权/取消和退出。每份记录标明实际已达阶段、工具是否动作、物理结果是否独立确认、缺失数据及配置版本。

历史HIL时长、旧夹具结果和干跑成功码不能作为新系统上线门；旧问题先核对当前源码与证据后再关闭。具体归并见[docs合并与基线](10_docs_merge_and_baseline.md)。

未知结果的处理

HTTP 超时 → 标结果未知 → 查询实际在途/终态 → 必要时发独立取消。浏览器中止等待不会取消 ROS goal；不得自动重发 POST。

剪切未确认的处理

工具 DI 窗口内无新沿 → CUT_UNCONFIRMED → 保持待人工。果实可能仍连枝，不自动正常撤离、不重发刀指令、不自动 resume。

保护停止/硬件急停由人处理现场与示教器复位；丢弃旧 goal，再重新下发。

剪切证据的三级表达

指令层

刀具命令已受理，level=4。只证明软件接口返回。

工具层

当前源码以工具 DI 新沿确认 level=5。反馈物理含义需现场校验。

产品层 · 建议强化

实际果梗脱离 + 撤退/承接的独立证据。当前level=7按切断与撤退的软件口径统计。

全面 Foxglove 化

浏览器直接连通用 ROS 桥

rosbridge/roslibjs成熟，但为这次改版扩大任意发布/服务面并增加重复入口，收益不足。

建议落地顺序

A 统一首屏、六步与证据表达 → B 操作登记、反馈来源、恢复与必要后端门 → C 只读回放/A-B → D 果梗/主枝与独立物理剪断验证。

新增安全相关门须在后端与臂侧强制并同轮更新包级文档；按钮灰化只能降低误操作。驱动栈保持只读，工具IO不直接暴露给浏览器。

# 端到端实测对比轮（round5）：方案候选 vs 原驱动，选最优落地

**日期** 2026-09-20（15:00–16:10） · **目标** 相机已连，按广域调研方案与原驱动（设备 18 图案深度 D 链）同帧组实测对比，端到端裁定最优并落地
**前置** sgbm-sweep（仪器+uniq6）、pointcloud-quality（med3）、better-algorithms（全分辨率档）、learned-stereo-live-test（零样本证伪）

## 0. 结论速览

1. **落地一项：`sgbm.mode: hh4`（默认档）**——端到端 12 变体矩阵帕累托最优：谷底一致性 **8.75→7.50mm（−14%）**、鬼影 **1.65→1.48%**、粗糙度 **1.03→0.94mm（−9%，低于设备链 1.08）**、覆盖 −0.34pp 门内，匹配 10.9→54ms 仍装进相机 73ms 帧间隔 → **live 13.7gps 零丢帧无回归**。新鲜场景（15:54 复抓）复验同序：谷底 9.00→8.00mm、鬼影 1.32→1.05%、粗糙度 1.08→1.00mm。
2. **HH4 是本轮最大意外收获**：半分辨率下 HH4 以 HH 一半时间（54 vs 116ms）拿到接近质量（7.50 vs 7.25mm）——OpenCV 4 路径向量化变体在相机节拍限速的停走场景里"免费"。
3. **端到端关键约束=发布率**：时域视差域 k3 融合覆盖 +4.5pp（47→51.5%）且精度门内，但批式 k3 发布率÷3（≈2–3Hz ≈ 设备链 2.43fps——09-17 轮 percipio 曾因慢帧输掉 observe_build_view_race），**记档不落地**。
4. **全分辨率精度档再证但门槛外的代价**：s100 系谷底 5.5–6.5mm 全场最优，但粗糙度 1.4–2.2mm（半分辨率 resize 自带 2×2 均值降噪，全分辨率裸噪声直接进配准网格）+ HH 匹配 386–990ms——精度换点云质量与帧率，不抵。
5. 场景静态性前置检查成立（D 链组间谷底 0.75–1.25mm @dx=0），时域融合评估方法论有效。

## 1. 方法

- 仪器：同帧组双链裁决（gridprobe4 采集 / repro_a.py 位级复现 A 链 + ctypes 真 SDK 配准 / sweep_metrics 三门 + 粗糙度）。变体矩阵脚本 `/tmp/lstereo/e2e_matrix.py`（shape 通用 med3/粗糙度 + 视差域时域融合 + HH/HH4/全分辨率 + 计时）。
- 帧组：09:45 组（3 组，上午场景）+ 15:54 新鲜组（3 组，当前场景，落地前复验）。
- 指标：覆盖%（0.3–1.5m）、谷底 |ΔZ| mm（横移扫描后 A vs D 共同窗中位）、鬼影%（1.5–2.5m）、边缘位移 px、粗糙度 mm（3×3 局部平面拟合残差中位）、匹配耗时 ms。门=谷底≤基线×1.10 / 鬼影≤+0.05pp / 边缘≤±2px。

## 3. 裁定逻辑（为什么是 hh4）

1. **发布率是端到端硬约束**：09-17 四续 percipio（2.43fps）败于 observe_build_view_race（帧慢+漂移门），stereo 13.5gps 胜出。任何发布率 ÷3 的批式融合（1.9–2.8Hz）都在向失败区靠拢；全分辨率+HH 的 386–990ms 匹配更是直接出局。
2. **hh4 在全指标上占优且零率损失**：54ms 匹配 + 链路其余开销仍 < 相机 73ms 帧间隔 → 组率仍由相机节拍决定（13.7gps 实测）。
3. **粗糙度是点云质量的本征指标**：半分辨率的 resize 均值自带降噪，全分辨率档谷底虽好但粗糙度 1.4–2.2mm 直接劣化点云（下游 RANSAC/法向/包络切片吃这个指标）。
4. 视差域时域融合的价值（覆盖 +4.5pp）留给未来"滑窗发布不除率"的实现（当前 avg_k 批式语义 ÷k），本轮不引入跨机位混帧风险。
